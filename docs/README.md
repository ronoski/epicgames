# Documentation index

This repository holds the **design specification** for an autonomous, scope-aware reconnaissance
workflow for Epic Games' authorized HackerOne bug-bounty program. No pipeline code yet — the data
model and safety model are meant to be redlined against a pinned target before anything touches the
network.

| Document | What it is |
|----------|------------|
| [`SPEC.md`](SPEC.md) | **Authoritative master spec** — purpose, ontology, per-datum calculus, event-sourcing, coverage/gap model, intelligence-domain index, Epic seed inventory, the autonomous-loop contract. |
| [`safety-model.md`](safety-model.md) | **Authoritative safety model** — `scope != ownership`, the closed recon-verb whitelist, the one unified per-target rate ledger, default-deny credential use, privacy rules, the client-RE hard stops + 12-check legal gate, and the machine-checkable invariants. |
| [`domains/binary-re.md`](domains/binary-re.md) | AI-synthesized **working reference** (pending verification) for the APK & binary reverse-engineering recon domain. Corrections banner at top. |
| [`domains/non-binary.md`](domains/non-binary.md) | AI-synthesized **working reference** (pending verification) for the 12 live/OSINT recon domains. Corrections banner at top. |
| [`../schema/`](../schema/) | JSON schemas: `ontology.json` (closed type registry), `node.schema.json` (the per-datum envelope), `event.schema.json`, `scope.schema.json`. |
| [`../configs/epicgames.example.yaml`](../configs/epicgames.example.yaml) | Example scope config skeleton — **must be filled from the live policy before use**. |

## Reading order

1. `SPEC.md` §1–§4 (what the data is and how it is kept).
2. `safety-model.md` (the non-negotiable controls).
3. `SPEC.md` §6 (the intelligence domains) → the two domain references for depth.
4. `SPEC.md` §7 (how the autonomous AI loop drives it) and §9 (what must be verified live).

## Provenance note

The two domain references were generated by multi-agent synthesis and then adversarially reviewed
for legal overreach, non-recon creep, intrusiveness, privacy, and fabricated specifics. The reviews'
fixes are consolidated into `SPEC.md` and `safety-model.md` (authoritative) and summarized in each
domain doc's corrections banner. Every concrete Epic identifier in the domain docs is a candidate to
verify against the live program/source — not fact.
